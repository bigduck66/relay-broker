# Vision: relay-broker

## Проблема

Нужен лёгкий брокер для асинхронной доставки сообщений между сервисами там, где критична надёжность (at-least-once), но не критичен строгий порядок — то есть независимые задачи/события, а не финансовые транзакции или лог изменений состояния.

## Позиционирование

В отличие от Kafka (упор на упорядоченный persistent log) или RabbitMQ (гибкая маршрутизация через exchange'и), наш брокер — простая in-memory push-модель, где вся сложность сосредоточена в надёжности (репликация + ack + DLQ), а не в порядке или персистентности.

## Ключевые возможности

- **At-least-once** — ack + retry/redelivery по таймауту
- **Push-модель** — брокер сам инициирует доставку подписчикам
- **In-memory хранилище** — низкая задержка, но данные не переживают одновременное падение всех реплик партиции (это стоит явно зафиксировать как принятое ограничение, а не пытаться закрыть отдельным persistence-слоем)
- **Репликация партиций** для отказоустойчивости
- **Настраиваемые ack levels** (0 / только лидер / кворум-все реплики — по аналогии с Kafka's acks)
- **Dead Letter Queue** для сообщений, не доставленных за N попыток
- **Горизонтальное масштабирование** через статическое партиционирование

## План

### Месяц 1 — ядро

Топики, push-подписка, in-memory хранилище, at-least-once на одном узле. Это уже рабочий MVP.

### Месяц 2 — надёжность

Репликация, ack levels, DLQ. Тесты на отказ узла с лидером партиции.

### Месяц 3 — партиционирование + несколько узлов

Нагрузочные тесты, документация и подготовка к защите.
